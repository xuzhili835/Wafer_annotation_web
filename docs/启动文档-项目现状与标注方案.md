# 光伏硅片缺陷检测 · 启动文档(项目现状与标注方案)

> 面向小组四人的项目现状说明与标注方案讨论稿。
> 事实数据全部来自 2026-09-16 的数据盘审计(可复现,脚本见文末),不是估计值。

## 省流(TL;DR)

- **干什么**:给 510 张训练图**画框 + 每框选缺陷代码**(12 选 1,或"本图无缺陷"),网页多人标注,全程留痕。
- **数据**:训练集 510 张零标注(本轮小组任务);测试集 537 图自带产线标注(932 框),只做评测与参照样例,**永不参与任何训练**。
- **最重要的一条**:目录名 ≠ 图里的缺陷 —— 一张图对应一份 XML,一份 XML 里可以有多个框、每个框各带一个类别代码;124 张图带 2 种以上代码,BX 目录 166 个框里 90 个是 X。标签一律以框为准。
- **协作**:token 进门(4 个永久令牌,权限完全平等);每张 2 人盲标打底,分歧自动加派第三人;多数票定稿,平票进全员盲审仲裁,可异议重审;每笔标注留痕可回放。
- **未知项**:缺陷代码官方中文名没拿到(先用推断+问号,拿到只改一张表);稀有码 BYW/KYW/XHB 照实标但暂不参与训练(策略可逆)。

## 一、这个项目要做什么

光伏硅片生产中表面会产生缺陷(隐裂、崩边、线痕等),人工目检达不到行业标准,要用深度学习做**缺陷检测**:在图上框出每处缺陷并判断类别,训出检测模型后接入看板自动分选。

与 PCB 项目的根本差异:

| | PCB 假点过滤 | 光伏硅片检测 |
|---|---|---|
| 任务形态 | 成对图**分类**(待检图+模板图 → 整图判一类) | 单图**目标检测**(画框,每框一个类别) |
| 标注动作 | 每张图选一个类 | 每处缺陷画一个框 + 选类 |
| 标签来源 | 文件夹名 = 类别 | VOC XML 里的 `<name>` 代码 |
| 数据现状 | 训练集曾散图待标(已标完) | **训练集 510 张零标注(本轮小组任务)** |

一句话记住光伏的标注对象:**一张图 ↔ 一份 XML;一份 XML 里可以有多个框,每个框各带一个类别代码**。所以"这张图属于哪一类"是个伪问题 —— 正确的问法是"这张图上有哪几处缺陷,各是什么代码"。目录名只是数据方的归档习惯(按主缺陷分文件夹),不代表图内全部内容。

## 二、数据现状(全部实测)

- **训练集**:510 张 png 散图(640×640 灰度,时间戳命名,如 `12.04.17.969_11.png`),**没有任何标注** —— 这是本轮要标的东西,共 202MB。
- **测试集**:537 张图,每张配一份同名词 XML(Pascal VOC 格式),共 **932 个缺陷框**;XML↔图片配对率 100%。
- **缺陷代码 12 个**(按框数):X 373 / HBB 117 / HBX 115 / HS 76 / BX 65 / KD 63 / DQK 51 / HB 49 / XQK 14 / BYW 5 / KYW 3 / XHB 1。
- 涉及 **377 片硅片**(同一片切多张图 —— 训练/验证必须按片分组切分,否则指标虚高,prepare.py 已内置)。
- 稀有代码:BYW(2 图)/ KYW(2 图)/ XHB(1 图)样本极少,无法参与训练与评测。
- **机械体检已通过**:重复图 0、越界/零面积框 0、未知代码 0。
- 测试集自带产线标注,既是评测基准也是我们的**标注格式样例**;其语义质量(框得对不对)未经人工复核,如需抽查另行安排。

## 三、关键发现(标注前必须知道的)

### 3.1 目录名 ≠ 图里的缺陷,训练标签以 XML 为准

测试集 9 个目录是数据方按"主缺陷"归档的,但**一张图上常有多种缺陷**:
- BX 目录 166 个框里只有 65 个 BX,90 个是 X;
- 全集 **124 张图带有 2 种及以上代码**;
- XQK / KYW / XHB 三个代码**只出现在 XML 里、没有自己的目录**。

结论:**目录名只当参考线索,一切以 XML(以及我们新标的框)为准**。这同时意味着:标注时不要因为图在哪个目录就预设它是什么缺陷。

### 3.2 缺陷代码没有官方中文名

数据方没给代码↔中文对照表。以下为**推断**(全部带问号,确认后只改一张表,网页帮助页附完整依据):

| 代码 | 推断 | 依据 |
|---|---|---|
| X | 线痕? | 需求书四类之一;全库最多(373 框/211 图) |
| BX | 崩边? | 需求书四类之一 |
| HS | 隐裂? | 需求书四类之一;框中位 609px 且 100% 贴边 —— 整片级裂纹形态,证据最强 |
| KD | 孔洞? | 拼音;10px 小点、仅 5% 贴边(片内小孔形态) |
| BYW | 边缘污? | 拼音;40% 贴边与"边缘"吻合 |
| HB / HBB | 黑斑类? | 11~13px 小点状,证据弱 |
| HBX | 复合缺陷? | 147px 中大框、70% 贴边;或为 HB+X 复合 |
| DQK / KYW / XQK / XHB | 待定 | 形态分别为 264px 大框82%贴边 / 4px 微点 / 小椭圆框 / 仅 1 框 |

### 3.3 没有PCB意义上的"假点",但要防"无缺陷图"

932 个框全部是缺陷代码,数据集没有"假点/OK"类(PCB 的假点是 AVI 误报,光伏场景不存在该概念)。**但训练集 510 张里可能存在无缺陷的干净图** —— 若有,必须作为"空标注(负样本)"落库,YOLO 训练需要一定比例背景图。标注工具会提供"本图无缺陷"按钮,请大家如实使用,不要硬找个框。

## 四、标注工作流(方案概要)

1. **认领与顺序**:系统按"每张恰好 2 人"预分配,每人约 340 张(个人队列随机洗牌,避免顺序效应);想多标自由加;进度板全透明,未分配的片任何人可接力。
2. **标注**:网页上看图 → 拖拽画框 → 快捷键选类别(12 码 + "本图无缺陷")→ 提交;每画一个框自动存草稿(本地+服务端双写);首次进入有强制分步新手引导,帮助页常驻图解手册;参照样例(测试集各类标准例+框叠加)侧栏常驻,每个代码悬停显示判定要点。
3. **留痕**:每次提交/改判/撤销都是一条新记录(谁、何时、哪个图、什么框、什么类),只追加不改写,全程可回放、可算每人一致率。
4. **交叉复标(自动)**:两人标注分歧的、预标低置信的、含稀有码的样本,自动追加派给第三人**盲标**——预计只占总量 15~25%,不显著加负担。
5. **定稿与仲裁(全组平等,无特权)**:
   - 同一张 ≥2 人标过 → **多数票**定稿;**平票进仲裁池**;
   - 仲裁视图**盲审**:定稿前不显示标注人真名(以甲/乙/丙/丁代替),投票后才解锁——防碍于情面、看人下菜;留痕表(审计用)随时可查历史;
   - **异议重审**:任何人可对已定稿的图一键"我有异议"+一句话理由,该图自动重开盲投;无理由不受理,防无限翻烧饼;
   - **封板**:任意一人发起,4 人中 3 人同意即锁定,锁定后方可导出"里程碑终版"。
6. **撤回**:对自己的标注,定稿前随时改判/撤销(均追加留痕);自己的历史任何时候可回看。
7. **预标注辅助(可选,建议做;自举式,不碰测试集)**:先由四人手工标一小批(约 100 张,尽量覆盖全部代码)→ 组长在**本地**训一个小 YOLO → 预标剩余约 410 张,生成建议框文件上传服务器 → 标注页里人工只做确认/修正。预标模型只见过人工标注的训练数据,测试集不参与任何训练,答辩口径干净(测试集只用于评测)。界面策略:建议框按置信度**分档呈现而非裸数字**(高:直接出框待确认;中:出框并提示"疑似 XX,建议对照参照样例";低:仅提示"本图可能仍有漏检"),页面明确标注"模型建议仅供参考",并混入少量盲测样本防止被模型带偏;
8. **导出(任何人、任何时候)**:服务端从数据库实时生成快照,永远自洽 —— 导出的就是纯数据,不存在"脚本与本地不同步"问题:
   - `annotations_<时间戳>.csv` 全量留痕表;
   - `labels_voted_<时间戳>.csv` 当前多数票定稿表;
   - `voc_xml_<时间戳>.zip` 与测试集同格式的 XML 包(解压与图同目录即喂 prepare.py)。
   平时导出用于看进度/自查;**训练只认封板后的里程碑终版**,不需要任何本地归类脚本。

### 4.1 已预判的坑与对策

| 可能的坑 | 对策 |
|---|---|
| 标到一半浏览器崩了 | 每画一个框自动存草稿(本地 + 服务端双写),点提交才计票 |
| 标错了 / 手滑提交 | 回看改判与撤销,均追加新记录、不改历史 |
| 有人拖延 | 进度板全透明;他人可"接力"未认领的片,不是抢 |
| 口径漂移(同一人前后不一致) | 每个代码悬停显示判定要点 tips,参照样例侧栏常驻 |
| 图片加载慢拖节奏 | 预加载下一张;640px png 单张仅几十 KB,2核2G 无压力 |
| 标签格式与训练脱节 | 工具直接导出与测试集同格式的 VOC XML,prepare.py 无缝接入 |
| 服务器数据丢失 | SQLite 定时备份到独立目录,每次部署前再拉一份回本地 |

**稀有码策略(建议,待小组讨论)**:标注界面保留全部 12 码,遇到照实标(量极小不费事);训练配置再决定忽略或合并 —— **数据不丢,策略可逆**。

## 五、平台与部署概要

- 标注工具:FastAPI + SQLite + 浏览器 canvas,部署在组长服务器(2核2G 足够;图片只读不动,标注只写库);
- 鉴权:4 个永久 token(`cmx/…`、`hce/…`、`zj/…`、`zzq/…` 前缀+随机串),页面首次粘贴存浏览器一周,过期重贴;
- 部署:沿用组内既有 GitHub Actions → SSH 模式(push 触发,三个 Secrets,服务器 deploy.sh 备份→重启→健康检查);域名走 Cloudflare 加子域 A 记录。

## 六、复现口径

- 数据审计:`python -m wafer.prepare`(概况,不落盘);
- 本文数字:交叉表/框形态/体检由 `xml.etree` 逐文件统计(537 XML 全量);
- 训练集张数/体积:`分类数据/硅片分类数据/硅片分类数据/训练集` 510 png / 202MB。
